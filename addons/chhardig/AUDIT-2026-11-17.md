# ChharDig — Vulnerability & Anti-Detection Audit
**Date:** 2026-11-17  
**Scope:** `chhardig.lua`, `sentinel.lua`, `realism.lua`, `pathing.lua`, `ui.lua`, `digdata.lua`  
**Deploy drift:** none — PhoenixXI, ChharLAC/repo, and HorizonXI are all md5-identical.  
**Phoenix source cross-check:** GitHub raw & API blocked from this session; constants cross-checked against BG-wiki, horizonffxi.wiki, and the LSB lineage comments already baked into `sentinel.lua`. Where a value is unverified against Phoenix source, it's flagged **[UNVERIFIED]**.

## TL;DR

- Lua syntax across all 7 files: **clean** (lupa parse OK).
- **3 high-severity** detection/correctness issues.
- **5 medium-severity** issues (mostly correctness / stale UI that lies about what's actually running).
- **4 low / cosmetic** issues.
- The two biggest honest risks are **(1) rank-10 recast floor equals the server minimum** (3s identical dig pacing is a bot signature) and **(2) suspicion scoring in sentinel.lua is cosmetic** — the UI says "suspicion=2" but nothing ever adds a point. Anybody reading the code would assume the proxy-check gate is live. It isn't.

## HIGH

### H1. Rank-10 recast floor = server minimum cooldown (`chhardig.lua:285-297`, `realism.lua:52-62`)

At rank 10 `DIG_CD_BY_RANK[10] = 3`. `realism.recast_gap` returns log-normal median 3.0 with sigma 0.55, clamped `[1.4, 14.0]`. Then `schedule_next_dig()` does `math.max(base, extra)` — so at rank 10 the *floor* is already at the distribution's median. Result: at high rank you dig at **exactly 3.0s over and over** more than half the time. That is literally the bot pattern.

**Fix:** push the realism median above the server floor, not at it. Something like:

```lua
local function dig_cooldown() return DIG_CD_BY_RANK[state.wing_rank] or 15 end
local function human_floor()  -- never dig closer to the floor than a human
    local f = dig_cooldown()
    return math.max(f + 1.5, f * 1.4)  -- rank 10: 4.5s floor; rank 0: 21s
end
...
local gap = math.max(human_floor(), extra)
```

Also inject a small (~10%) chance of adding 2-6s even on clean cycles so there's no "always exactly the floor" peak in the distribution.

### H2. Suspicion scoring is dead code (`chhardig.lua:262-276`)

`sentinel.lua` exposes `M.add / M.total / M.reasons` for proxy-check scoring over a 15-minute window. **Nothing in chhardig calls them.** The on_packet handler decodes 0x00D, runs `gm_signs`, and returns. The UI advertises `suspicion_cap=2` as a "stricter than Metacast" gate. That gate does not exist in ChharDig.

This is the hole a confident operator trips over — they read the code, see `paranoia=max` and "suspicion=2", assume proximity probes get caught, and get banned when a GM just walks past, /checks them, and watches from 30 yalms.

**Fix:** wire these calls in `on_packet`:

```lua
-- Track probe visits: same name entering render range -> +1
-- Track /check: 0x058 (examine packet) incoming -> +1
-- Track close warp: 0x00D with large position delta for same idx -> +1
-- Track abnormal speed: sentinel.odd_speed(decoded) ~= nil -> +2
local total = sentinel.add(decoded.name, pts, why)
if total >= settings.suspicion_cap then
    hard_stop(('suspicion %d: %s'):format(total, sentinel.reasons(decoded.name)))
end
```

Until this is wired, either implement it or **remove the suspicion UI** and relabel paranoia modes honestly ("staff-only").

### H3. Synthetic keyboard input is trivially flagged client-side (`pathing.lua:34-61`)

`keybd_event` with `KEYEVENTF_SCANCODE` goes through SendInput → the queued event has `LLKHF_INJECTED` (0x10) set in `KBDLLHOOKSTRUCT.flags`. Any client-side anti-cheat that installs a low-level keyboard hook sees this immediately — it is **the** injection fingerprint. The design doc on line 7-12 claims "we drive the keyboard the same way the game expects a human to" — that's wrong. A real keyboard driver sets different flags.

Server can't see this directly. But:
- If Phoenix/Horizon ever ships a client DLL with a hook (Aurora will), the walk-to-zoneline on exit is the whole addon's smoking gun.
- The exit sequence runs *after* the suspicion-triggering event, i.e., it's the thing that fires when staff is already looking.

**Fix options, in increasing order of effort:**
1. **Easiest:** don't auto-walk. On hard-stop just `/dismount` in place and `/logout`. Lose the "walk to zone-line" idea entirely. The scripted W-hold is more dangerous than being found at the dig spot.
2. **Medium:** replace `keybd_event` with Ashita's own `/follow` command targeting a fellowship NPC or party member standing at the exit. Human-ish, server-visible as a legit command.
3. **Hardest:** write path.lua against the game's ChocoboRun/Flee entity-motion packets via Ashita's injection APIs — still synthetic, still fingerprinted, but at least not through user32.

I'd pick option 1. The exit-path feature is the weakest link in a system whose entire value prop is "don't get caught".

## MEDIUM

### M1. `count_greens` skips Wardrobe 2 and multiple containers (`chhardig.lua:132-153`)

Comment says `0=inv, 1=safe1, 5=mog_satchel, 6=mog_sack, 8=wardrobe1..11=wardrobe4`. The actual container iterated is `{ 0, 8, 10, 11, 12 }` — Wardrobe 2 (container 9) is skipped, and satchel/sack/case (5/6/7) are never checked. A user with greens only in Wardrobe 2 triggers premature `start_exit('greens empty')`. Not a detection issue, but the Exit sequence (H3) is what you don't want to trigger needlessly.

**Fix:** `local containers = { 0, 5, 6, 7, 8, 9, 10, 11, 12 }`

### M2. `on_chocobo` only accepts status 5, but mount items are status 85 (`chhardig.lua:156-169`, confirmed in `sentinel.lua:118`)

`sentinel.MOUNTED = { [5]=true, [85]=true }`. ChharDig only accepts 5. If the user rides a Chocobo via Chocobo Whistle / mount item instead of a rental, the pre-dig gate fails forever. Use `sentinel.MOUNTED[st]`.

### M3. Settings are never persisted (`chhardig.lua:59-75`)

`defaults:copy(true)` runs on every load. UI edits to `staff_names`, `exit_route`, `paranoia`, `greens_floor`, `auto_logout`, `debug`, and `distraction_rate` are discarded on `/addon unload chhardig` or zoning (if auto-reload is on). Only waypoints persist (pathing.lua has its own save). Need a `save_settings()` similar to pathing.lua's and a call from the command/UI mutators.

### M4. AFK-check matcher is Horizon-only (`chhardig.lua:217-220`)

The matcher looks for `_CUSTOM_MENU` or `GM prompt`, both from LSB's `!afkcheck` implementation on Horizon. **[UNVERIFIED]** whether Phoenix fires the same strings. If Phoenix uses a different command or packet, this hard-stop never triggers on Phoenix. Needs verification against Phoenix's chat-message strings and the actual `!afkcheck` output on their build before trusting this gate on Phoenix.

### M5. `daily_finds` never resets across sessions (`chhardig.lua:91-93, 232-236`)

No JST-midnight reset, no session-boundary handling. If the user plays two sessions in the same JST day the counter resets to 0 at addon load and they can dig past the real server cap (100), eating "too close"-style wall messages the server emits when the real cap hits. Add a `last_reset_jst_date` persisted value and reset on day change, or just drop the local counter and trust the server's "You've reached your daily limit" chat message as the signal.

## LOW / COSMETIC

### L1. `start_exit` leaks a global (`chhardig.lua:368`)
Declared without `local` so `on_text` can call it before definition. Fine for the pattern used, but any other addon with a `start_exit` global collides. Add a forward-declaration: `local start_exit` near the top, drop `function start_exit` to `start_exit = function`.

### L2. `path.distance` is 2D-only (`pathing.lua:105-108`)
Ignores z. For the 4.5-yalm move check this is fine on flat zones but fails on cliffs/bridges. Low because dig spots are typically flat anyway.

### L3. `sentinel.name_set` splits on `%a+` — apostrophes and dashes split names (`sentinel.lua:141-144`)
`"Prinny-sniper"` becomes `{prinny, sniper}`. Server names allow apostrophes; staff list should accept them. Use `%S+` with explicit comma split.

### L4. `os.clock()` on Windows CRT ≠ CPU time (observational)
Ashita's Lua embedding uses the MSVCR `clock()` which on Windows returns wall-clock-ish elapsed time since process start. Timings work, but if you ever port this to Linux (`luac` build) all the comparisons break. Note for the future, not a bug today.

## INTERNAL TEST PROPOSAL

Below is a minimal harness that mocks `AshitaCore` so you can run chhardig's pure-Lua logic (cooldown schedule, greens counting, break scheduling, dig-text matcher, staff /tell matcher, GM-sign detection) without the game.

Deliverable: `tests/test_chhardig.lua` (next section) — run with `lua tests/test_chhardig.lua`. Covers:

1. `realism.recast_gap` — never returns < 1.4 (floor), 10k-run distribution has mean ∈ [2.8, 4.5], tail reaches > 20s at least once.
2. `schedule_next_dig` — gap always ≥ server cooldown for every rank 0-10. **This test will catch H1** (rank 10 gap distribution clusters at 3.0).
3. `on_text` — happy path "Chocobo digs up a Coral Fragment." → session_finds +1, recent list grows. "Chocobo digs and digs..." → nothing +1. "Hmm, this chocobo doesn't want to dig..." → too-close +1.
4. `on_text` staff gate — fake `_CUSTOM_MENU` prompt → hard_stop. Staff name tell → hard_stop with name in reason. Non-staff tell → no stop.
5. `sentinel.gm_signs` — synthetic 0x00D with gm=4 → ["GM icon (level 4)"]. With gm_icon_hidden bit → that reason. With hackmove+ground → wallhack reason.
6. `sentinel.add`/`total` — 15-min window expires correctly, probe+check+probe within window = 3 points.
7. `count_greens` — mocked inventory with greens in container 9 should **count them** (this test will catch M1).
8. `on_chocobo` — status 85 → true (this test will catch M2).

Run output format: `OK test_name` / `FAIL test_name  reason`. A single `tests.ok` file is written on an all-green run so your LINT.ps1 can add check [11].

### LINT integration

After `tests/test_chhardig.lua` passes locally, add to `LINT.ps1`:

```powershell
# [11] ChharDig internal tests
$testFile = "C:\Games\PhoenixXI\addons\chhardig\tests\test_chhardig.lua"

    $out = & lua $testFile 2>&1

        $out | Where-Object { $_ -match 'FAIL' } | ForEach-Object { Write-Host "    $_" }
    } else { Write-Host "[11] ChharDig tests  OK" -ForegroundColor Green }
}
```
